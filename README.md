# CheckStock — Веб-прототип складского учёта и контроля движения товаров

Веб-прототип системы сквозного учёта товарных остатков по складам фулфилмента (ФФ) и маркетплейсам (FBO / FBS).  
Позволяет менеджеру в реальном времени видеть, **где сейчас находится товар, сколько единиц доступно к продаже и что находится в пути**.

Стек: **Python 3.13, FastAPI, SQLite (aiosqlite) / PostgreSQL (asyncpg), SQLAlchemy 2.0, Pydantic v2, Pytest, Tailwind CSS**.

---

## Быстрый запуск

По умолчанию проект настроен на работу с **асинхронным SQLite (`aiosqlite`)**, поэтому запускается сразу «из коробки» без необходимости поднимать или настраивать внешние серверы баз данных.

### 1. Клонирование и виртуальное окружение
```bash
git clone <url_репозитория>
cd CheckStock
python -m venv .venv
```

Активация виртуального окружения:
- **Windows (PowerShell)**: `.\.venv\Scripts\Activate.ps1`
- **Linux / macOS**: `source .venv/bin/activate`

### 2. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 3. Конфигурация (.env)
Скопируйте шаблон переменных окружения:
```bash
cp .env.example .env
```
*(По умолчанию в файле уже прописан SQLite: `DATABASE_URL=sqlite+aiosqlite:///./checkstock.db`. Если вы хотите подключить PostgreSQL, достаточно раскомментировать соответствующую строчку в `.env`)*.

### 4. Запуск сервера
```bash
uvicorn app.main:app --reload
```

При первом старте приложение **автоматически создаёт таблицы и загружает тестовые данные строго по ТЗ**:
- Склады: «Север» и «Юг»
- Артикулы и остатки:
  - `SKU-101` Органайзер: Север — 10, Юг — 6
  - `SKU-102` Контейнер: Север — 5, Юг — 0
  - `SKU-103` Корзина: Север — 0, Юг — 4

После запуска откройте в браузере:
- **Веб-интерфейс**: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- **Swagger API (документация эндпоинтов)**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## Ключевые архитектурные решения

### 1. Расчёт остатков без риска рассинхронизации
В базе данных физически сохраняются только две базовые величины:
- `physical_qty` — фактическое наличие товара на складе.
- `reserved_fbs_qty` — количество единиц, заблокированных под клиентские заказы FBS.

Доступный остаток рассчитывается динамически как вычисляемое свойство (`property`):
```python
available_qty = max(0, physical_qty - reserved_fbs_qty)
```

*Обоснование*: хранение доступного остатка в отдельной колонке БД неизбежно приводит к рассинхрону при конкурентных запросах или частичных сбоях. Вычисляемое свойство гарантирует 100% математическую точность.

### 2. Умная обработка нехватки товара (Shortage Detection)
При попытке зарезервировать или отгрузить больше товара, чем доступно на выбранном складе:
1. Система проверяет свободные остатки по всем остальным активным складам сети.
2. Если суммарно по сети товара достаточно, бэкенд возвращает статус `STOCK_SHORTAGE` с пояснением:
   > *«Нехватка товара SKU-102 на складе 'Юг': запрошено 2 шт., доступно только 0 шт. (не хватает 2 шт.). Однако суммарно по сети доступно 5 шт. ('Север': 5 шт.). Рекомендуется оформить перемещение между складами!»*
3. В интерфейсе появляется модальное окно с кнопкой в 1 клик для оформления перемещения с склада-донора.

### 3. Мягкое удаление склада (Soft Delete)
Требование ТЗ: *«При удалении сохраните остатки и историю. Покажите, где числится товар»*.
- При удалении склад помечается `is_active = False` («В архиве»).
- Физические остатки, резервы и журнал операций сохраняются.
- В интерфейсе склад отображается с пометкой «(В архиве)», а система выводит предупреждение о количестве оставшихся на нём товаров.

### 4. Идемпотентность и защита от повторного списания
Операции перемещения, резервирования и отгрузок поддерживают параметр `idempotency_key` и проверяют текущий статус сущности:
- Повторный клик или сбой сети не приводят к двойному списанию или начислению товара.

### 5. Сквозной журнал аудита (Event Ledger)
Каждое изменение остатка фиксируется в таблице `operation_logs` (`INCOME`, `MOVEMENT_SEND`, `MOVEMENT_RECEIVE`, `FBS_RESERVE`, `FBS_CANCEL_RESERVE`, `FBS_SHIP`, `FBO_SHIP`, `FBO_RECEIVE`).

## Автоматические тесты

Запуск тестов:
```bash
pytest -v
```

Тесты проверяют ключевые сценарии ТЗ в изолированной среде:
- `test_overview_seeded` — проверка стартовых остатков по ТЗ.
- `test_shortage_detection` — выявление нехватки на одном складе при наличии на другом.
- `test_movement_and_idempotency` — перемещение между ФФ и защита от повторной приёмки.
- `test_soft_delete_warehouse` — архивация склада с сохранением остатков.
- `test_fbs_flow_and_double_shipment` — резервирование, списание и защита от повторного клика.
- `test_fbo_flow_and_receiving` — отгрузка на склад маркетплейса и фиксация приёмки.
